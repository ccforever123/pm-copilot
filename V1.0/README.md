# V1.0 模板说明

来源：微信公众号：松鼠的AI笔记。

## 文件结构

```text
V1.0/
├── CLAUDE.md
└── templates/
    ├── 需求说明文档模板.html
    └── 原型备注模板.html
```

## CLAUDE.md 的流程和作用

`CLAUDE.md` 是给 Claude Code 使用的产品需求助理执行说明文件。它把 AI 的工作方式固定成一套可恢复、可审查、可交付的需求生产流程，核心目标是协助产品经理完成需求拆解、需求文档生成、页面原型生成，以及后续变更同步。

### 1. 启动与状态恢复

每次加载后，`CLAUDE.md` 要求先检查项目根目录下的 `.pm_state.json` 状态文件。

- 如果状态文件存在，则读取当前阶段、需求文档、原型文件夹、上次中断点等信息，并从中断处继续。
- 如果状态文件不存在，则扫描是否已有 `*_需求说明_*.md` 文档，用现有交付物推断当前状态。
- 如果既没有状态文件，也没有交付物，则进入全新需求启动流程。

这个机制的作用是避免长流程中断后丢失上下文，让需求拆解、文档生成、原型生成都可以继续推进。

### 2. 阶段一：需求拆解

AI 会先从用户描述中提取产品目标、目标用户、使用场景、功能列表、功能边界和非功能需求。

`CLAUDE.md` 特别强调：不能默认接受模糊需求。遇到描述模糊、信息缺失、逻辑冲突、范围过大或技术不可行时，必须先指出并追问，不能自行脑补后继续生成。

阶段一结束后，AI 会输出功能拆解清单，并等待用户明确确认。

### 3. 阶段二：生成需求文档

用户确认功能拆解后，AI 会读取 `templates/需求说明文档模板.html`，按照模板结构生成完整需求文档，并保存为类似：

```text
{功能名称}_需求说明_v1.0.md
```

生成后会进入 review 流程，由 subagent 从逻辑完整性、表达清晰度、技术可行性、内部一致性等维度审查文档。审查发现阻断或重要问题时，需要先修正文档并重新 review；通过后再等待用户确认定稿。

### 4. 阶段三：生成页面原型

需求文档定稿后，AI 会询问是否需要生成 HTML 页面原型。

如果用户选择生成，流程会先确认页面清单，然后创建与需求文档同名的原型文件夹，并基于 `templates/原型备注模板.html` 生成页面原型。原型要求包含真实 UI 结构、可点击导航、交互状态、逻辑备注和页面说明。

生成后同样需要 subagent review，检查原型与需求文档是否一致。

### 5. 阶段四：变更同步

当需求文档和页面原型都已定稿后，任意一方发生变更，都需要触发同步规则：

- 修改需求文档后，询问是否同步修改页面原型。
- 修改页面原型后，询问是否同步修改需求文档。
- 文件版本号随变更升级，例如 `v1.0` 升级到 `v1.1` 或 `v2.0`。
- `.pm_state.json` 中的文档路径和原型文件夹路径也要同步更新。

这保证需求文档和页面原型始终保持一致，减少产品、设计、开发、测试之间的信息偏差。

## 需求文档模板亮点

`templates/需求说明文档模板.html` 不只是静态文档模板，它内置了可编辑能力：

- 双击文档正文区域，可以直接进入编辑状态。
- 编辑后页面右上角会出现保存工具条。
- 点击保存后，可以保存 HTML 文件。
- 保存时选择原文件并覆盖，即可更新当前需求文档。

这个设计让需求文档可以像普通网页一样阅读，又能在浏览器里直接修改正文内容，适合产品评审、现场改稿和快速更新需求说明。

## 适用场景

这套 V1.0 模板适合用于：

- 从零梳理产品需求。
- 将口头需求整理成结构化需求文档。
- 基于需求文档生成 HTML 页面原型。
- 在需求变更后同步维护文档和原型。
- 让产品、设计、前端、后端、测试围绕同一份交付物协作。
