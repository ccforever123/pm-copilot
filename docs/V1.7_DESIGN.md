# V1.7 完整梳理

## 1. 版本定位

V1.7 的定位是：**可恢复的产品交付 Harness + 多专家评审 + 多文档模板体系**。

它不是把原 PM Copilot 和 V1.6 简单堆在一起，而是明确三层职责：

- Harness 状态机：负责启动、恢复、节点推进、checkpoint、同步和交付。
- 多文档模板：负责前期分析、日常产品文档和 PRD 内容结构。
- 多专家评审：负责按需审查质量、挑战假设、补齐风险。

最终交付目标仍是 PRD、prototype 和 demo。

## 2. V1.6 保留内容

V1.7 保留 V1.6 的所有核心逻辑：

- `rules/startup.md` 的最小启动链路。
- `rules/guardrails.md` 的读取边界和确认规则。
- `.pm_state.json` 的状态恢复字段。
- `memory/handoff.md` 的新对话恢复入口。
- `memory/process/` 的过程摘要。
- Markdown PRD 构建 HTML 的 `scripts/build_requirement_html.py`。
- `prototype/` 和 `demo/` 的版本隔离。
- `sync_workflow.md` 的变更同步确认机制。
- Sub-Agent 并行分发规则。

变化是：`prd/` 被升级为 `documents/`，以支持 PRD 和其他文档共存。

## 3. 新增能力

### 3.1 需求入口判断

用户输入“我要做一个 xxx 软件”时，先判断需求清晰度。足够清晰则进入 PRD；不够清晰则提供工具选项。

入口判断减少两种问题：

- 一上来强行写 PRD，导致大量待确认项。
- 追问过多，用户不知道如何回答。

### 3.2 前期分析工具

前期工具不改变最终目标，而是帮助 PRD 更清晰：

- 头脑风暴产品方向。
- 用户画像。
- JTBD。
- 竞品分析。
- 机会方案树。
- 优先级决策矩阵。

生成结果全部进入 `documents/`，后续 PRD 会读取并汇总来源。

### 3.3 多文档模板库

V1.7 纳入 9 个阶段的产品经理文档模板。默认不加载全文，只在用户选择具体文档后读取。

### 3.4 多专家评审

专家作为 review agent 使用：

- 按模板头部选择专家。
- 自定义模板按 `recommended_experts` 选择专家。
- PRD 默认 UX、Dev、Industry、Auditor。
- Auditor 按阶段加载 checklist。

专家评审不会替代主流程，也不会常驻上下文。

### 3.5 documents 信息归并

生成 PRD 前必须汇总已有 documents：

```text
信息 -> 来源文件 -> 拟写入章节 -> 用户确认
```

只有用户确认后，信息才可进入 PRD。

### 3.6 冲突处理

documents 中信息冲突时，必须列出冲突来源，询问用户：

- 修改来源 A。
- 修改来源 B。
- 同步两份文档。
- 保留差异并说明适用边界。

### 3.7 out_files 交付出口

`documents/`、`prototype/`、`demo/` 是工作源；`out_files/` 是交付出口。

定稿或验证通过后，交付物同步到：

```text
out_files/documents/
out_files/prototype/
out_files/demo/
```

## 4. 主流程

```text
需求输入
  -> 需求清晰度判断
  -> 前期分析工具选择或直接 PRD
  -> documents 信息归并与确认
  -> PRD Markdown
  -> PRD HTML
  -> 多专家评审
  -> PRD 定稿
  -> prototype / demo / prototype_then_demo
  -> review 或验证
  -> out_files 归档
```

## 5. 文档路由方案

非 PRD 文档只在三种情况下生成：

1. 用户明确要求。
2. 用户在需求不清晰时选择前期分析工具。
3. 生成 PRD 前发现必须补齐某类分析，并得到用户确认。

模板路由由 `rules/template_routing.md` 控制。

## 6. 专家评审方案

专家评审由 `rules/expert_review.md` 控制：

- 先识别文档阶段和模板专家。
- 再读取必要专家 skill。
- 最后读取 Auditor 和对应 checklist。

输出必须包含 PASS / WARNING / FAIL，以及阻断、重要、建议三类问题。

## 7. 文件管理方案

```text
documents/     工作中的文档源文件和 HTML 构建产物
prototype/     工作中的原型
demo/          工作中的 demo
out_files/     定稿或验证通过后的交付出口
```

`out_files/` 不反向覆盖工作目录，除非用户明确要求。

## 8. 文档阅读器

`document_reader.html` 是本地阅读辅助工具，解决 documents 增多后查看不方便的问题。它不参与状态机，不是交付源文件。

## 9. 后续可选增强

- 给 `documents/_index.md` 增加自动摘要字段。
- 给 `out_files/` 增加一键压缩脚本。
- 给模板路由增加关键词匹配表。
- 给专家评审增加更细的阶段 checklist 映射。
