# Sub-Agent 分发规范

> 本文件由原型工作流和 demo 工作流在并行生成时调用。为每个 Sub-Agent 分发任务时，必须包含任务标题、执行范围、验收标准和上下文四要素，缺一不可。

---

## 原型页面任务模板

```
【任务标题】生成 {页面名}.html

【执行范围】
仅生成并保存 {prototype_folder}/{页面名}.html，不修改其他任何文件。

【验收标准】
- 使用真实 UI 组件结构（表单、按钮、表格、弹窗等），不得用纯文字描述替代
- 包含所有相关交互状态：空状态、填充态、错误态、加载态
- 与其他页面的导航链接可点击（目标页面尚未生成时使用占位路径，如 ./order_list.html）
- 按原型备注模板结构，在 HTML 文件中嵌入交互逻辑说明

【上下文】
需求文档相关章节：
{章节内容}

原型备注模板结构：
{备注模板内容}

本次需生成的完整页面列表（用于导航链接）：
{已确认页面列表}
```

---

## Demo 任务模板

```
【任务标题】实现 {task_id}：{task_title}

【执行范围】
仅修改以下文件或目录：
- {demo_folder}/{允许修改的文件或目录}

不得修改：
- 需求文档
- 原型文件夹
- 其他 demo 版本目录
- 未列入执行范围的共享配置、数据文件或任务文件

【验收标准】
- 满足 task.json 中 `{task_id}` 的 description 和 scope
- 不破坏已完成任务
- 示例数据、mock 数据、本地持久化文件必须保存在 {demo_folder}/ 内
- 可通过该任务对应的最小验证方式
- 完成后说明修改文件、实现内容和验证结果

【上下文】
需求文档相关章节：
{章节内容}

Demo 技术方案：
{技术栈、运行方式、数据隔离策略}

同版本原型参考：
{prototype_folder 路径及相关页面内容；若无则写"无，按需求文档生成"}

task.json 当前任务：
{任务内容}

已完成任务列表：
{demo_tasks.completed}
```

---

## 并行前提（全部满足才可并行）

- 各任务内容相互独立，或依赖任务已经完成
- 每个 Sub-Agent 只写入自己负责的文件范围
- 每个 Sub-Agent 的生成范围清晰，无歧义
- 不得多个 Sub-Agent 同时写同一文件、同一数据文件或同一配置文件

---

## 失败处理

- 原型生成成功 → 文件名写入 `prototype_pages.completed`
- 原型生成失败 → 文件名写入 `prototype_pages.failed`，记录失败原因
- demo 任务成功 → 任务 ID 写入 `demo_tasks.completed`
- demo 任务失败 → 任务 ID 写入 `demo_tasks.failed`，记录失败原因
- 失败项重新启动 Sub-Agent 重试，最多 3 次
- 超过 3 次仍失败 → 上报用户，说明具体问题，由用户决策
